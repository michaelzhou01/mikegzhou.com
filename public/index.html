01 anatomy of a request

  1. request
  2. tokenize
  3. batch
  4. prefill
  5. decode
  6. stream
00 / request

A prompt arrives.

Somewhere, someone asks a model a question. The clock starts now.

01 / tokenize

Text becomes integers.

The prompt is split into tokens, and each token is an id in the model's vocabulary.

02 / batch

Share the GPU.

Many requests run side by side. When one finishes, the next takes its slot right away. That's continuous batching.

03 / prefill

Read it all at once.

The whole prompt goes through the model in one parallel pass, filling the KV cache as it goes.

04 / decode

Then one token at a time.

Each new token attends to everything before it. The cache grows a page at a time.

05 / stream

Back to you.

Tokens stream out as they're made: a fast first token, then a steady rhythm.

02 speculative decoding

  1. draft
  2. verify
  3. commit
00 / draft

Guess ahead.

A small, fast model drafts the next few tokens. Each guess is cheap.

01 / verify

Check every guess at once.

The big model scores all the drafts in a single forward pass and keeps them up to the first miss.

02 / commit

Several tokens, one pass.

The accepted tokens plus one correction land together. The output is identical, just faster.

03 quantization

  1. bf16
  2. fp8
  3. int4
00 / bf16

Sixteen bits a weight.

A 70B-parameter model at 16 bits is about 140 GB, more than any single GPU holds.

01 / fp8

Half the bits.

Snap each weight to a coarser grid. The model barely notices, and memory traffic halves.

02 / int4

Sixteen levels.

Now you can see the grid. The art is choosing where those levels fall, so it still fits and still thinks.
