01 about

I work on the part of the stack that takes a trained model and makes it answer quickly, cheaply, and at scale, at Reflection. Here's roughly what that involves.

02 anatomy of a request

  1. request
  2. tokenize
  3. batch
  4. prefill
  5. decode
  6. stream
00 / request

A prompt arrives.

Somewhere, someone asks a model a question. The clock starts now.

01 / tokenize

Text becomes integers.

The prompt is split into tokens, and each token is an id in the model's vocabulary.

02 / batch

Share the GPU.

Many requests run side by side. When one finishes, the next takes its slot right away. That's continuous batching.

03 / prefill

Read it all at once.

The whole prompt goes through the model in one parallel pass, filling the KV cache as it goes.

04 / decode

Then one token at a time.

Each new token attends to everything before it. The cache grows a page at a time.

05 / stream

Back to you.

Tokens stream out as they're made: a fast first token, then a steady rhythm.

03 mixture of experts

  1. route
  2. compute
  3. balance
00 / route

Pick two experts.

A small router scores every expert for each token and sends it to the top two.

01 / compute

Most weights sit out.

Each token runs through only 2 of 8 expert networks, so the model is huge but each token is cheap.

02 / balance

Keep the load even.

If the router favours a few experts, they overflow while others sit idle. Training adds a balancing term to spread the work.

04 latency vs. throughput

Batch until it hurts.

Bigger batches share each read of the weights across more users, so total throughput climbs. But every request’s KV cache is read every step too, so with long contexts the GPU stays memory-bound, and runs out of memory, long before compute is the limit.
